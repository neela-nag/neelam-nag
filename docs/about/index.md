## What I believe about documentation

Every page has to earn its place by serving a specific user intent — not the product's structure, not the engineering team's mental model, but the question the user arrived with and the outcome they need to leave with.

Good documentation is a system, not a collection of pages. The structural decisions — what belongs on which page, how content is organised, how legacy content is handled, how shared content is maintained — are as important as the writing itself. Often more so.

Documentation that the support team trusts enough to use as their primary reference has succeeded. Documentation that sits unread has not, regardless of how well it is written.
